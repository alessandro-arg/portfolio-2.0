In den letzten Wochen hatte ich nicht so viel Zeit für Linux, wie ich gerne gehabt hätte, weil ich Umgezogen bin. Zwischen Kartons auspacken und alles einrichten musste auch mein Homelab etwas umgestellt werden. Obwohl ich wenig Zeit hatte, konnte ich trotzdem praktische Erfahrung mit Linux-Benutzern, Gruppen und Berechtigungen sammeln. Interessantes Thema. Es hat mir geholfen, besser zu verstehen, wie Linux Zugriff, Sicherheit und Verantwortung zwischen verschiedenen Benutzern auf einem System verwaltet.

Viele Konzepte ergeben deutlich mehr Sinn, sobald man versteht, wem eine Datei gehört, wer darauf zugreifen darf und warum nicht jeder Root Permissions haben sollte.

## Was ich gemacht habe

Ich habe damit begonnen, mir die Benutzerverwaltung anzusehen und herauszufinden, als welcher Benutzer ich aktuell angemeldet bin.

Befehle wie <Hl>who</Hl> und <Hl>w</Hl> zeigen Informationen über angemeldete Benutzer und aktive Sitzungen.

Außerdem habe ich den Befehl `id` ausprobiert:

```bash
id
```

Beispielausgabe in meinem Fall:

```bash
uid=1000(user) gid=1003(user) groups=1003(user),4(adm),20(dialout),
24(cdrom),27(sudo),29(audio),44(video),46(plugdev),60(games),
100(users),107(netdev),992(render),995(input),1000(gpio),1001(spi),1002(i2c)
```

Das zeigt:

- <Hl>uid</Hl> - Deine Benutzer-ID
- <Hl>gid</Hl> - Deine primäre Gruppen-ID
- <Hl>groups</Hl> - Alle Gruppen, zu denen du gehörst

### Benutzer verstehen

Jeder Benutzer hat:

- einen Benutzernamen (wie <Hl>user</Hl>)
- eine Benutzer ID-Nummer (wie <Hl>1000</Hl>)
- ein Home Verzeichnis (wie <Hl>/home/user</Hl>)
- eine Default Shell (wie <Hl>/bin/bash</Hl>)

Benutzerinformationen werden in `/etc/passwd` gespeichert:

```bash
cat /etc/passwd
```

Jede Zeile steht für einen Benutzer:

```text
yourusername:x:1000:1000:Your Name:/home/yourusername:/bin/bash
```

Das `x` bedeutet, dass der eigentliche Passwort-Hash an anderer Stelle gespeichert wird, nämlich in `/etc/shadow`.

### Gruppen verstehen

Gruppen ermöglichen es mehreren Benutzern, gemeinsamen Zugriff auf Dateien zu haben. Die Gruppen kann man so ansehen:

```bash
cat /etc/group
```

Und jede Zeile sieht ungefähr so aus:

```bash
sudo:x:27:yourusername
```

Man sieht also, dass das Format ungefähr so aufgebaut ist: `groupname:passowrd:gid:members`

Einige der häufigsten Gruppen sind:

- `sudo` - darf sudo-Befehle verwenden
- `adm` - darf Logdateien lesen
- `www-data` - Webserver-Gruppe
- `docker` - darf Docker verwenden

### Einen Benutzer erstellen

Danach habe ich geübt, Benutzer zu erstellen und zu entfernen:

```bash
sudo adduser testuser
```

Man muss ein Passwort setzen und kann einige optionale Informationen wie Name, Firma usw. angeben. (Mit Enter überspringt man die optionalen Felder und lässt sie leer)

Das erstellt:

- ein neues Benutzerkonto
- ein Home Verzeichnis `/home/testuser`
- eine Gruppe mit demselben Namen

### Einen Benutzer löschen

```bash
sudo deluser testuser
```

Um auch das Home Verzeichnis des Benutzers zu entfernen:

```bash
sudo deluser --remove-home testuser
```

## Dateiberechtigungen

Die Ausgabe von `ls -l` zu verstehen, war anfangs gar nicht so einfach.

Zum Beispiel:

```bash
ls -l /etc/passwd
```

Ausgabe:

```text
-rw-r--r-- 1 root root 1842 Dec 10 14:30 /etc/passwd
```

Am Anfang hatte ich keine Ahnung, was ich da eigentlich anschaue.

Sobald ich die einzelnen Teile verstanden habe, war es gar nicht mehr so kompliziert:

```bash
-rw-r--r--  1  root  root  1842  Dec 10 14:30  /etc/passwd
│├─┤├─┤├─┤ │   │     │     │         │           │
│ │  │  │  │   │     │     │         │           └── Filename
│ │  │  │  │   │     │     │         └── Modification date
│ │  │  │  │   │     │     └── Size in bytes
│ │  │  │  │   │     └── Group owner
│ │  │  │  │   └── User owner
│ │  │  │  └── Number of hard links
│ │  │  └── Others permissions
│ │  └── Group permissions
│ └── Owner permissions
└── File type (- = file, d = directory, l = link)
```

Ich musste mich auch daran gewöhnen, Berechtigungen aus drei verschiedenen Perspektiven zu denken: Besitzer, Gruppe und Others.

Das war am Anfang ein bissle verwirrend, aber nach ein paar Tests hat es langsam Klick gemacht.

### Die Berechtigungstypen

Beispiel:

```bash
-rw-r--r--    Regular file, owner can read/write, others can only read
-rwxr-xr-x  Executable, owner full access, others can read/execute
drwxr-xr-x  Directory, owner full access, others can read/enter
-rw-------      File only owner can read/write (private)
```

### Berechtigungen ändern: chmod

Einer der nützlichsten Befehle, die ich gelernt habe, war `chmod`, mit dem man Dateiberechtigungen ändert.

Symbolischer Modus:

```bash
chmod u+x script.sh    # Add execute for user (owner)
chmod g+w file.txt     # Add write for group
chmod o-r file.txt     # Remove read for others
chmod a+r file.txt     # Add read for all (a = all)
chmod u+rwx file.txt   # Add read, write, execute for user
```

Dabei gilt:

- `u` = user
- `g` = group
- `o` = others
- `a` = all
- `+` = Berechtigung hinzufügen
- `-` = Berechtigung entfernen

Ich habe auch die numerische Methode gelernt.

Berechtigungswerte:

```text
r = 4
w = 2
x = 1
```

Häufige Kombinationen:

```bash
chmod 755 script.sh    # rwxr-xr-x  (executable by all)
chmod 644 file.txt     # rw-r--r--    (readable by all)
chmod 600 secret.txt   # rw-------      (private file)
chmod 700 private_dir  # rwx------      (private directory)
```

Befehle wie `chmod 755` hatte ich schon gesehen, aber nie wirklich verstanden. Jetzt weiß ich, dass sie einfach Kombinationen aus Lese-, Schreib- und Ausführungsrechten sind.

### Besitzrechte ändern: chown

Besitzer ändern:

```bash
sudo chown username file.txt
```

Gruppe ändern:

```bash
sudo chgrp developers file.txt
```

Rekursiv (für Verzeichnisse):

```bash
sudo chown -R user:group directory/
```

## Sudo und Root

Ein weiteres interessantes Thema war der Root Benutzer.

Root (auch superuser genannt) hat die UID 0 und kann im Grunde alles auf dem System tun:

- jede Datei lesen
- jede Datei verändern
- jeden Prozess beenden
- Systemeinstellungen ändern

Genau diese Macht ist der Grund, warum man normalerweise nicht den ganzen Tag als Root arbeitet.<br />
Ein einziger Tippfehler kann ein System beschädigen.<br />
Alles als Root auszuführen erhöht außerdem Sicherheitsrisiken, weil ein Malware zum Beispiel sofort vollständigen Zugriff hätte.

Stattdessen verwendet Linux `sudo`, um Berechtigungen bei Bedarf temporär zu erhöhen.

Zum Beispiel:

```bash
sudo apt update        # Update packages (needs root)
sudo vi /etc/hosts     # Edit system file (needs root)
sudo cat /etc/shadow   # View passwords file (needs root)

```

### Sudo Timeout

Nachdem man das eigene Passwort eingegeben hat, merkt sich sudo die Authentifizierung für eine kurze Zeit. Man wird nicht sofort erneut gefragt.

Um das manuell zurückzusetzen:

```bash
sudo -k
```

### Eine Root Shell starten

Um eine Root Shell zu öffnen:

```bash
sudo -i
```

Dadurch erhält man eine Root Shell. Der Prompt ändert sich von `$` zu `#`.

Mit `exit` kommt man wieder zurück zum normalen Benutzer.

<Callout type="warning">
  Warnung: Sei in einer Root Shell extrem vorsichtig. Lass sie nicht offen.
</Callout>

Der Zusammenhang zwischen Benutzern, Gruppen, Besitzrechten und Berechtigungen ist jetzt deutlich klarer. Ich sehe, warum Linux so entworfen wurde, besonders wenn mehrere Benutzer dasselbe System verwenden.

Die wichtigste Erkenntnis für mich war, dass Berechtigungen nicht nur mit Sicherheit zu tun haben. Es geht auch darum, Verantwortung zu steuern und Fehler zu vermeiden.
