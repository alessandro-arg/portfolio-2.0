Im letzten Beitrag habe ich über das Dateisystem und Paketverwaltung gesprochen. Diese Woche habe ich mehr Zeit damit verbracht zu lernen, wie Dateien funktionieren, wie man Dateiinhalte anzeigt, nach Text sucht und Dateiinformationen auf einfache Weise versteht.

Noch geht es nicht darum, Dateien zu bearbeiten. Eher darum zu verstehen, wie man sie inspiziert, durchsucht und herausfindet, was auf dem System selbst passiert.

Ich wollte das Verzeichnis `/etc` etwas genauer erkunden und verstehen, wie Menschen Linux-Systeme tatsächlich direkt vom Terminal aus untersuchen. Ich habe mir einige Videos von Mischa van den Burg angesehen, der Linux- und DevOps-Themen sehr praxisnah erklärt.

Normalerweise brauche ich unter Windows Excel oder eine andere GUI-Anwendung, wenn ich eine Datei wie .xlsx öffnen möchte. Unter Linux kann man viele Dinge direkt im Terminal inspizieren, ohne zuerst ein grafisches Programm zu öffnen. Das fühlt sich für mich manchmal immer noch ungewohnt an, aber auch wirklich mächtig.

## Was ich gemacht habe

Die ersten Befehle, mit denen ich herumgespielt habe, waren `cat` und `grep`.

`cat` gibt einfach den Dateiinhalt im Terminal aus.

```bash
cat /etc/passwd
```

Das klingt simpel, verändert aber die Art, wie man mit einem System interagiert. Wenn man auf Servern arbeitet, besonders ohne Desktop-Umgebung, wird es sehr wichtig, Dateien schnell inspizieren zu können.

Außerdem gibt es `head` und `tail`. <br />
Standardmäßig zeigen sie die ersten oder letzten 10 Zeilen an, aber man kann das anpassen:

```bash
head -20 /etc/passwd
tail -20 /etc/passwd
```

Der Befehl, der mir am meisten aufgefallen ist, war dieser:

```bash
tail -f /var/log/syslog
```

Das `-f` steht für follow. <br />
Anstatt die Datei nur einmal auszugeben, beobachtet Linux die Datei weiter und aktualisiert das Terminal in Echtzeit, sobald sich etwas ändert.

Logs live auf diese Weise zu beobachten, fand ich ehrlich gesagt richtig cool. Ich habe sofort verstanden, warum Menschen das zum Debuggen von Servern und Anwendungen verwenden.

Ich habe auch viel Zeit damit verbracht, mit `grep` zu experimentieren.

```bash
grep "error" /var/log/syslog
```

Das sucht nach allen Zeilen, die `"error"` enthalten.

Danach habe ich verschiedene Flags ausprobiert:

- `grep -i` → ignoriert Groß- und Kleinschreibung und findet auch Zeilen mit "ERROR"
- `grep -n` → zeigt Zeilennummern an
- `grep -v` → zeigt Zeilen an, die NICHT übereinstimmen
- `grep -r` → sucht rekursiv durch Verzeichnisse
- `grep -c` → zählt die Treffer
- `grep -B` und `grep -A` → zeigt die Zeilen vor oder nach dem Treffer
- `grep -C` → kombiniert die Flags -B und -A

Ich habe auch gelernt, dass `grep` Muster unterstützt und nicht nur einfachen Text.

- `^` → bedeutet 'beginnt mit' ("^error")
- `$` → bedeutet 'endet mit' ("err$")
- `[0-9]` → findet beliebige Ziffern

Ich brauche später definitiv mehr Übung mit Mustern und Regex, aber ich sehe jetzt schon, wie nützlich das ist.

Eine andere Sache, die ich mich gefragt habe, war:

## Was für ein Dateityp ist das?

Dafür habe ich den Befehl `file` verwendet:

```bash
file /bin/ls
```

Ausgabe:

```bash
/bin/ls: ELF 64-bit LSB pie executable, ARM aarch64, version 1 (SYSV),
dynamically linked, interpreter /lib/ld-linux-aarch64.so.1,
BuildID[sha1]=19a53698c72a1d765f961ccd04bff6665434c0f5,
for GNU/Linux 3.7.0, stripped
```

Das fand ich super interessant. <br />
Man sieht sofort:

- ausführbarer Dateityp
- CPU-Architektur
- Linking-Informationen
- Zielbetriebssystem

Ohne irgendetwas zu öffnen.

Für noch mehr Details habe ich `stat` verwendet.

```bash
stat /etc/passwd
```

Das zeigt Berechtigungen, Zeitstempel, Besitzrechte, Inode-Informationen und vieles mehr:

```bash

Device: 179,2 Inode: 6561 Links: 1

Modify: 2026-05-11 22:32:14.652197778 +0200
Change: 2026-05-11 22:32:14.658197728 +0200
Birth: 2026-05-11 22:32:14.652197778 +0200
```

### Wörter, Zeilen und Zeichen

Dafür gibt es `wc`.

```bash
wc /etc/passwd
```

Und die Flags:

- `wc -l`
- `wc -w`
- `wc -c`

Um Zeilen, Wörter und Zeichen separat zu zählen.

### Speicherbelegung & freier Speicherplatz

Am Ende habe ich Befehle rund um Speicherplatz erkundet:

- `du -sh` → disk usage
- `df -sh` → disk free space

Das Flag `-h` macht die Ausgabe menschenlesbar, was definitiv einfacher zu verstehen ist als rohe Bytes, und das Flag `-s` fasst die Ausgabe zusammen.

Der Befehl `df` zeigt alle eingehängten Dateisysteme und deren Speicherbelegung. <br />
Ich kann jetzt schon sagen, dass diese Befehle später Teil meines täglichen Workflows werden.
