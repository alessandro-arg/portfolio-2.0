Als jemand, der normalerweise den Großteil des Tages in VS Code verbringt, fühlte sich ein Texteditor im Terminal etwas altmodisch an. Ich kannte `nano` und `vim`, war mir aber nicht wirklich sicher, welchen Editor ich zuerst lernen sollte.

Die meisten Anfänger scheinen mit Nano anzufangen, weil es einfach und leicht verständlich ist.

Warum habe ich mich also entschieden, mit vi anzufangen? <br/>
Weil es überall verfügbar ist.

Egal ob Linux Server, Unix System, macOS, ein minimaler Docker Container oder irgendein Embedded System; vi sollte bereits installiert sein. Wenn ich mich per SSH auf einen Server verbinde und schnell eine Datei ändern muss, kann ich nicht davon ausgehen, dass `VS Code` oder `nano` verfügbar sind.

## Was ich gemacht habe

Eines der ersten Dinge die ich gelernt habe ist, dass `vi` unter Ubuntu eigentlich `vim` ist.

```bash
ls -la /usr/bin/vi
```

Output:

```bash
lrwxrwxrwx 1 root root ... /usr/bin/vi -> /etc/alternatives/vi
```

Wenn man dem Symlink folgt:

```bash
ls -la /etc/alternatives/vi
```

Output:

```bash
lrwxrwxrwx 1 root root ... /etc/alternatives/vi -> /usr/bin/vim.basic
```

Auch wenn ich also `vi` eingebe, benutze ich in eigentlich vim.

Das ist beim Lernen ganz praktisch, aber es ist auch gut zu wissen dass viele Container nicht die vollständige vim-experience mitbringen.

Die berühmte "hjkl"-Navigation war mir nicht bekannt. Ich fand sie lustig und gleichzeitig seltsam.

```text
h = links
j = runter
k = hoch
l = rechts
```

Mein Gehirn wollte automatisch ständig die Pfeiltasten benutzen. Nach einer Weile habe ich verstanden, warum viele Leute damit arbeiten. Die Hände dauerhaft auf der Tastatur zu lassen, ohne ständig zu den Pfeiltasten zu wechseln, fühlt sich tatsächlich ziemlich effizient an. Aber ja, ich benutze trotzdem noch die Pfeiltasten lol.

## Wo ich Schwierigkeiten hatte

Der schwierigste Teil war nicht die Navigation durch Dateien.

Vim funktioniert komplett anders als die Editoren die ich bis jetzt benutzt habe. <br/>
Am Anfang habe ich eine Datei geöffnet, angefangen zu tippen und mich gefragt, warum nichts passiert.

Dann habe ich die zwei "Modes" gefunden.

Es gibt:

- `Normal Mode` für Befehle
- `Insert Mode` zum Schreiben von Text

Jetzt alles deutlich weniger verwirrend.

Ich hatte auch einige Momente, in denen ich vergessen hatte, wie man vim wieder verlässt...

```bash
:wq
```

zum Speichern und Beenden.

```bash
:q!
```

zum Beenden ohne Speichern.

Heute simpel, aber definitiv nicht intuitiv am ersten Tag.

## Busybox vi ausprobieren

Ich habe mir außerdem etwas Zeit genommen, um `busybox` anzusehen.

Busybox liefert schlanke Versionen vieler Linux-Werkzeuge und wird häufig verwendet in:

- Docker Containern
- Embedded Systemen
- Routern
- Recovery Umgebungen

Um zu sehen, wie ein minimalistischer Editor aussieht, habe ich Busybox installiert und Folgendes ausprobiert:

```bash
busybox vi test.txt
```

Die Unterschiede sind sofort aufgefallen:

- Kein `-- INSERT --`-Hinweis
- Kein Syntax Highlighting
- Nur eine Undo-Stufe

Es fühlt sich ein bisschen einfacher an als vim.

Alle Befehle die ich gerade lerne, funktionieren auch dort. Deshalb versuche ich mich zuerst auf die Grundlagen zu konzentrieren, statt direkt viele vim-spezifische Shortcuts zu lernen.

## Was ich gelernt habe

Im Moment möchte ich mir diese Befehle ohne nachzudenken merken:

1. `i` - Mit dem Schreiben beginnen
2. `Esc` - Insert Mode verlassen
3. `:wq` - Speichern und beenden
4. `:q!` - Ohne Speichern beenden
5. `dd` - Eine ganze Zeile löschen
6. `u` - Rückgängig machen

Das reicht ehrlich gesagt für die meisten Situationen, die mir aktuell begegnen werden.

Außerdem habe ich noch ein paar zusätzliche Befehle gelernt:

7. `x` - Ein Zeichen löschen
8. `o` - Eine neue Zeile erstellen und direkt schreiben

Noch nichts Fortgeschrittenes, aber genug, um Änderungen vorzunehmen, ohne komplett verloren zu sein.

Außerdem habe ich `vimtutor` entdeckt. Das ist wahrscheinlich die beste Ressource, die ich bisher gefunden habe. Statt Videos anzuschauen, konnte ich die Befehle direkt im Editor in einer separaten Lernumgebung ausprobieren.

## Fazit

Ich finde `vim` lässt sich einfacher bedienen als gedacht.

Klar, es ist anders und die erste Stunde kann frustrierend sein. Aber sobald ich aufgehört habe, es wie VS Code benutzen zu wollen und akzeptiert habe dass es anders funktioniert, war es relativ straight forward.

Von echter Routine bin ich noch weit entfernt, aber ich fühle mich jetzt schon deutlich wohler dabei, Dateien direkt im Terminal zu öffnen und zu bearbeiten.

Mein Plan ist erstmal einfach: weiter mit `vimtutor` üben, Muscle Memory aufbauen und aufhören, alle paar Wochen zu googeln, wie man vim beendet...

### Wichtigste Erkenntnisse

- Vi ist auf fast jedem Linux System verfügbar.
- Unter Ubuntu ist `vi` meistens vim im Hintergrund.
- Der größte Stolperstein ist das Verständnis von Normal Mode und Insert Mode.
- `hjkl` fühlt sich anfangs seltsam an, wird aber überraschend natürlich.
- Busybox vi entspricht eher dem, was man in schlanken Containern vorfindet.
- Man braucht nur eine Handvoll Befehle, um produktiv zu werden.
