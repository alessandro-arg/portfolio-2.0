Diese Woche wollte ich mich wohler dabei fühlen, Dateien zu bearbeiten. <br/>
Als jemand, der normalerweise den Großteil des Tages in VS Code verbringt, fühlte sich ein Texteditor im Terminal zunächst etwas altmodisch an. Ich kannte `nano` und `vim`, war mir aber nicht wirklich sicher, welchen Editor ich zuerst lernen sollte.

Die meisten Anfänger scheinen mit Nano anzufangen, weil es einfach und leicht verständlich ist. Vim hat den Ruf, sehr mächtig zu sein, aber auch verwirrend.

Warum habe ich mich also entschieden, mit vi anzufangen? <br/>
Weil es überall verfügbar ist.

Egal ob Linux-Server, Unix-System, macOS, ein minimaler Docker-Container oder irgendein eingebettetes Gerät – die Wahrscheinlichkeit ist hoch, dass vi bereits installiert ist. Wenn ich mich per SSH auf einen Server verbinde und schnell eine Konfigurationsdatei ändern muss, kann ich nicht davon ausgehen, dass `VS Code` oder `nano` verfügbar sind.

Wie Mischa van den Burg es ausdrückte:

<Quote>
  Jedes Linux-System hat vi. Lerne es einmal und nutze es für immer.
</Quote>

Das hat mich überzeugt.

## Was ich gemacht habe

Eines der ersten Dinge, die ich gelernt habe, ist, dass `vi` unter Ubuntu eigentlich Vim ist.

```bash
ls -la /usr/bin/vi
```

Ausgabe:

```bash
lrwxrwxrwx 1 root root ... /usr/bin/vi -> /etc/alternatives/vi
```

Wenn man dem Symlink folgt:

```bash
ls -la /etc/alternatives/vi
```

Ausgabe:

```bash
lrwxrwxrwx 1 root root ... /etc/alternatives/vi -> /usr/bin/vim.basic
```

Auch wenn ich also `vi` eingebe, benutze ich in Wirklichkeit Vim.

Das ist beim Lernen ganz praktisch, aber es ist auch gut zu wissen, dass viele Produktionscontainer nicht die vollständige Vim-Erfahrung mitbringen.

Die berühmte `hjkl`-Navigation war ein weiteres Thema, das ich endlich ausprobieren konnte.

```text
h = links
j = runter
k = hoch
l = rechts
```

Ganz ehrlich: Am Anfang fühlte sich das ziemlich lächerlich an.

Mein Gehirn wollte automatisch ständig die Pfeiltasten benutzen. Nach einer Weile begann ich aber zu verstehen, warum viele Leute damit arbeiten. Die Hände dauerhaft auf der Tastatur zu lassen, ohne ständig zu den Pfeiltasten zu wechseln, fühlt sich tatsächlich ziemlich effizient an. Aber ja, ich benutze trotzdem noch die Pfeiltasten lol.

## Wo ich Schwierigkeiten hatte

Der schwierigste Teil war nicht die Navigation durch Dateien.

Es war zu verstehen, dass Vim komplett anders funktioniert als die Editoren, die ich gewohnt bin.

Am Anfang habe ich eine Datei geöffnet, angefangen zu tippen und mich gefragt, warum nichts passiert.

Genau da hat das ganze Konzept der "Modi" endlich Klick gemacht.

Es gibt:

- `Normal Mode` für Befehle
- `Insert Mode` zum Schreiben von Text

Sobald ich das verstanden hatte, wurde alles deutlich weniger verwirrend.

Ich hatte auch einige Momente, in denen ich vergessen hatte, wie man Vim wieder verlässt.

```bash
:wq
```

zum Speichern und Beenden.

```bash
:q!
```

zum Beenden ohne Speichern.

Heute simpel, aber definitiv nicht intuitiv am ersten Tag.

## Busybox vi ausprobieren

Ich habe mir außerdem etwas Zeit genommen, um `busybox` anzusehen.

Busybox liefert schlanke Versionen vieler Linux-Werkzeuge und wird häufig verwendet in:

- Docker-Containern
- Embedded-Systemen
- Routern
- Recovery-Umgebungen

Um zu sehen, wie ein minimalistischer Editor aussieht, habe ich Busybox installiert und Folgendes ausprobiert:

```bash
busybox vi test.txt
```

Die Unterschiede sind sofort aufgefallen:

- Kein `-- INSERT --`-Hinweis
- Kein Syntax Highlighting
- Nur eine Undo-Stufe

Es fühlt sich deutlich einfacher an als Vim.

Interessant fand ich, dass alle Befehle, die ich gerade lerne, dort trotzdem funktionieren. Deshalb versuche ich mich zuerst auf die Grundlagen zu konzentrieren, statt direkt viele Vim-spezifische Shortcuts zu lernen.

## Was ich gelernt habe

Im Moment möchte ich diese Befehle ohne nachzudenken beherrschen:

1. `i` - Mit dem Schreiben beginnen
2. `Esc` - Insert Mode verlassen
3. `:wq` - Speichern und beenden
4. `:q!` - Ohne Speichern beenden
5. `dd` - Eine Zeile löschen
6. `u` - Rückgängig machen

Das reicht ehrlich gesagt für die meisten Situationen, die mir aktuell begegnen werden.

Außerdem habe ich noch ein paar zusätzliche Befehle gelernt:

7. `x` - Ein Zeichen löschen
8. `o` - Eine neue Zeile erstellen und direkt schreiben

Noch nichts Fortgeschrittenes, aber genug, um Änderungen vorzunehmen, ohne komplett verloren zu sein.

Außerdem habe ich `vimtutor` entdeckt. Das ist wahrscheinlich die beste Ressource, die ich bisher gefunden habe. Statt Videos anzuschauen, konnte ich die Befehle direkt im Editor in einer separaten Lernumgebung ausprobieren.

## Fazit

Ich glaube, Vim hat einen einschüchternderen Ruf, als es eigentlich verdient.

Klar, es ist anders und die erste Stunde kann frustrierend sein. Aber sobald ich aufgehört habe, es wie VS Code benutzen zu wollen und akzeptiert habe, dass es anders funktioniert, ergab vieles deutlich mehr Sinn.

Von echter Routine bin ich noch weit entfernt, aber ich fühle mich jetzt schon deutlich wohler dabei, Dateien direkt im Terminal zu öffnen und zu bearbeiten.

Mein Plan ist erstmal einfach: weiter mit `vimtutor` üben, Muskelgedächtnis aufbauen und aufhören, alle paar Wochen zu googeln, wie man Vim beendet...

### Wichtigste Erkenntnisse

- Vi ist auf fast jedem Linux-System verfügbar.
- Unter Ubuntu ist `vi` meistens Vim im Hintergrund.
- Der größte Stolperstein ist das Verständnis von Normal Mode und Insert Mode.
- `hjkl` fühlt sich anfangs seltsam an, wird aber überraschend natürlich.
- Busybox vi entspricht eher dem, was man in schlanken Containern vorfindet.
- Man braucht nur eine Handvoll Befehle, um produktiv zu werden.
