I finally spent proper time experimenting instead of just copying commands from tutorials without understanding what they actually do.

This week was mostly about building a foundation: navigating the filesystem, understanding how Linux is organized internally, learning package management, and getting more comfortable working directly with the terminal.

I also managed to break my Ubuntu installation...
I was trying to create a pipeline that analyzes /etc/passwd. I wanted to:

- <Hl>cut -d: -f1 /etc/passwd</Hl> → extract just the usernames (first field)
- <Hl>+ | sort</Hl> → sort them alphabetically
- <Hl>+ | wc -l</Hl> → count how many there are
- <Hl>+ | tee users.txt</Hl> → save the sorted list to
  <Hl>users.txt</Hl>
  and show it on screen

This is now correct, but i'm pretty sure that i worte something like: <br/> <Hl>cat /etc/passwd | cut -d: -f1 | sort > users.txt</Hl>

I somehow moved the content of <Hl>passwd</Hl> inside the <Hl>user.txt</Hl> file, and then deleted it...

After that, the terminal stopped working properly. I wanted to log out and reconnect via SSH to refresh the session, but then I realized I couldn’t log into the system anymore lol.

## What I made

I spent a lot of time just experimenting directly with the terminal and trying to understand how the system behaves. I also practiced moving around the filesystem with <Hl>cd</Hl>, <Hl>pwd</Hl>, <Hl>ls</Hl> and <Hl>ls -la</Hl>.

That helped me finally understand the difference between absolute and relative paths.

I spent a while exploring the Linux directory structure too. <br />
Some folders that finally started making sense:

- <Hl>/home</Hl> → personal user files
- <Hl>/etc</Hl> → system configuration
- <Hl>/var</Hl> → logs and changing system data
- <Hl>/dev</Hl> → devices
- <Hl>/root</Hl> → home directory of the root user

One thing I kept hearing before was:

<Quote>Everything in Linux is a file.</Quote>

Now I finally understand what people mean by that. <br />
Not only documents, but also devices, processes, sockets, and other system resources are exposed through files or file-like interfaces.

That concept felt weird at first, but pretty clever.

## Package management

Another big topic was package management. <br />
I learned what a package actually is and how the package manager handles software installation, updates, dependencies, and removal.

Since I'm using Ubuntu, I worked with APT.

I also learned that every Linux distribution has its own package manager:

| Distribution    | Package Manager | Command |
| --------------- | --------------- | ------- |
| Ubuntu / Debian | APT             | apt     |
| Fedora / RHEL   | DNF             | dnf     |
| Arch Linux      | Pacman          | pacman  |
| Alpine          | APK             | apk     |

I didn't realize before how much control package managers actually have over the system. <br/>
Especially on Arch Linux, people always warn you not to randomly install packages without being 100% sure that they are legit.

## The moment I deleted the users

While experimenting, I somehow ended up deleting:

```bash
/etc/passwd
```

Not my smartest moment. <br/>
Honestly though, it was kind of funny lol.

At first I thought maybe I could fix it manually, but the installation was on an SD card and there was nothing important on it. So I just reinstalled Ubuntu and started over.

A good reminder that Linux gives you a lot of freedom, but also enough freedom to completely destroy your own system.

## What I learned

The biggest thing I learned is that Linux starts becoming much less intimidating once you understand the structure behind it.

Now I slowly start understanding:

- where files live
- how commands are discovered
- how software gets installed
- how the filesystem is organized
- how to read help pages
- how shell builtins differ from normal commands

I also discovered:

```bash
man ls
ls --help
help cd
```

The difference between <Hl>man</Hl>, <Hl>--help</Hl>, and <Hl>help</Hl> was surprisingly useful to understand.

Especially because commands like cd are shell builtins and don't behave exactly like normal binaries.

I also learned the difference between:

```bash
find
locate
```

<Hl>find</Hl> actively searches the filesystem, while <Hl>locate</Hl> uses a
database index and is much faster.

Small detail, but useful once you start searching through a lot of files.
