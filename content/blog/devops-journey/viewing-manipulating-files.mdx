# Viewing & Manipulating Files on Linux

I spent some more time exploring Linux fundamentals, especially around files and directories.

Coming from Windows, I was always used to opening a program first before I could inspect a file properly. On Linux, it feels very different. You can investigate almost everything directly from the terminal, even without opening an editor.

My goal this time was simple: understand how to inspect files, search through logs and get information about what is happening on a system.

I mainly explored the `/etc` directory and watched some videos from DevOps Engineer Mischa van den Burg, which helped me understand why these commands are so important in real environments.

## Was ich gemacht habe

One thing that immediately stood out to me is how powerful simple commands already are.

With `cat`, I can directly print file contents into the terminal:

```bash
cat /etc/passwd
```

That sounds basic, but it changes how you interact with a system. Instead of opening an editor, you can quickly inspect configuration files or logs directly from the shell.

I also learned about `head` and `tail`.

```bash
head /etc/passwd
tail /etc/passwd
```

By default they show the first or last 10 lines, but you can customize it:

```bash
head -20 /etc/passwd
tail -20 /etc/passwd
```

What I found really cool was `tail -f`.

```bash
tail -f /var/log/syslog
```

This lets you watch files in real time while they are changing. I immediately understood why this is useful for logs and debugging.

Another big topic was `grep`.

I already heard about it many times before, but now I finally started using it myself.

```bash
grep "error" /var/log/syslog
```

This searches for all lines containing `"error"`.

I also tested different flags:

```bash
grep -i "error" /var/log/syslog
```

Ignore uppercase and lowercase.

```bash
grep -n "error" /var/log/syslog
```

Show line numbers.

```bash
grep -v "error" /var/log/syslog
```

Show lines that do NOT match.

```bash
grep -r "error" /etc
```

Search recursively through directories.

I also learned that `grep` supports patterns and not only plain text.

```bash
^
```

Means "starts with".

```bash
$
```

Means "ends with".

```bash
[0-9]
```

Matches digits.

This was the moment where Linux started feeling less like "just commands" and more like an actual toolkit for investigating systems.

I also wanted to understand what kind of files exist on Linux systems.

For that I used the `file` command:

```bash
file /bin/ls
```

Output:

```bash
/bin/ls: ELF 64-bit LSB pie executable, ARM aarch64, version 1 (SYSV), dynamically linked...
```

I found this surprisingly interesting.

You immediately see:

- executable type
- CPU architecture
- linking information
- operating system target

Without opening anything.

For even more details, I used `stat`.

```bash
stat /etc/passwd
```

This shows permissions, timestamps, ownership, inode information and much more.

I also learned about `wc`:

```bash
wc /etc/passwd
```

And the flags:

```bash
wc -l
wc -w
wc -c
```

For counting lines, words and characters separately.

At the end I explored storage related commands:

```bash
du -h
```

Disk usage.

```bash
df -h
```

Disk free space.

The `-h` flag makes the output human-readable, which is definitely easier to understand than raw bytes.

I can already tell these commands will become part of my daily workflow later.

## Probleme unterwegs

No major problems this time.

Most of the session was exploration and experimentation.

I mainly tried commands against real directories and logs on my Raspberry Pi to better understand what they actually do.

## Was ich gelernt habe

I think this was one of the first moments where Linux started feeling practical instead of theoretical.

Before that, the terminal still felt a bit abstract to me.

Now I slowly understand why Linux administrators and DevOps engineers work so heavily in the shell. You can inspect almost everything directly from the command line without needing a GUI.

A few things that stood out to me:

- logs become much easier to inspect with `tail -f`
- `grep` is insanely powerful
- Linux exposes a lot of system information directly through files
- commands like `stat`, `file`, `du` and `df` help understand what is actually happening on the machine

None of this feels advanced yet, but it feels foundational.

And honestly, I like that.
